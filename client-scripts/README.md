# Client Communication Scripts — Freelancer Training Series

A set of professional conversation scripts designed to train freelancers in client discovery, requirement gathering, solution presentation, and project closing. All scripts are focused on automation and integration projects using platforms such as Monday.com, GoHighLevel, Make.com, n8n, Wix, and other business tools.

## How to Use These Scripts

### For Team Training
1. **Read-through:** Have team members read the script independently and highlight phrases they would use in their own calls.
2. **Role play:** Pair team members — one plays the freelancer, one plays the client. Switch roles.
3. **Debrief:** After each role play, review the "Key Lessons" table at the end of the script and discuss what was done well and what could be stronger.
4. **Live shadowing:** Once a team member is comfortable with the scripts, have them shadow a real discovery call before running one independently.

### Key Principles Running Through Every Script

**1. Discover before proposing**
Never propose a solution before you fully understand the current state (Point A) and the desired outcome (Point B). Clients often request the wrong thing — your job is to uncover what they actually need.

**2. Reflect back before moving forward**
Before presenting a solution, summarize what you heard. This builds trust, catches misunderstandings early, and positions you as someone who listens.

**3. Educate, don't just sell**
The best freelancers make clients smarter on every call. Explain why something works, what the risks are, what to watch out for. Clients who feel educated become long-term clients.

**4. Always close with a specific next step**
Never end a call with "I'll be in touch." End with a specific deliverable, a specific timeline, and a specific ask of the client.

**5. Never surprise a client with cost**
If anything is going to cost extra, say so before you do the work. This single principle builds more trust than any sales technique.

## Common Objections and Responses

| Objection | Response Approach |
|---|---|
| "This seems expensive" | Reframe as ROI — what does the manual process cost in time, errors, and missed opportunities? |
| "Can you do this cheaper?" | Reduce scope, not your rate — offer a Phase 1 that solves the highest-impact problem first |
| "I've tried automation before and it broke" | Validate their experience, then explain specifically what makes your build different |
| "Can we just add this one small thing?" | Always scope it before agreeing — "small" is relative; some "small" requests are hours of work |
| "We might switch tools later" | Address directly: explain how you build for portability and document everything |
| "I need to think about it" | Acknowledge, then ask: "Is there a specific part you'd like more clarity on before deciding?" |

## Glossary of Terms Used in Scripts

| Term | Meaning |
|---|---|
| **Point A / Point B** | Current state vs. desired future state — always define both before scoping |
| **Webhook** | A real-time data push from one platform to another when an event occurs |
| **Polling** | A scheduled check where an automation platform asks "did anything change?" at regular intervals |
| **Bi-directional sync** | Data flowing both ways between two platforms — changes in either system update the other |
| **Scope creep** | When a client adds requests beyond what was originally agreed and priced |
| **Retainer** | A monthly ongoing service fee for maintenance, monitoring, and small modifications |
| **Make.com scenario** | A single automated workflow built inside Make.com |
| **n8n workflow** | A single automated workflow built inside n8n |
| **CTA (Call to Action)** | A button or prompt that asks a visitor to take a specific action (book a call, join waitlist, etc.) |
