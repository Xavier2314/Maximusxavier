# Video production

Weak videos usually fail on the plan, not the render: no hook, no single message,
captions nobody can read, audio that clips or is too quiet. Work through the stages
below in order. Skip a stage only when the user has already supplied its output, for
example a finished script.

## 1. Lock the brief (ask only for what is missing)

| Field | Default if the user doesn't say |
|---|---|
| Platform and aspect | TikTok/Reels/Shorts → 9:16 1080×1920. YouTube/web → 16:9 1920×1080. Feed ad → 1:1 or 4:5 |
| Length | Short-form 20–45 s. Ad 15 or 30 s. Explainer 60–120 s |
| Single goal | One sentence: what should the viewer do or believe at the end? |
| Audience | Who it's for and what they already know |
| Assets | Logo, brand colors, footage, images, voice. Note anything that has to be generated |
| Route | See step 3 |

Write the brief back to the user in 4–6 lines before producing anything longer than 30 s.

## 2. Script and shot list

Read `references/scripting.md` for hook formulas, pacing and caption rules. The
non-negotiables:

- **Hook in the first 1–2 seconds.** Use visual motion and an on-screen line together. Never open on a logo.
- **One idea per shot.** Change shots every 1.5–3 s for short-form and 3–6 s for explainers.
- **Write for the ear.** Use short sentences. At about 150 words per minute of voiceover, 30 s is roughly 75 words.
- **Plan for silent viewing.** Burn in captions, and make sure the video still makes sense with the sound off.
- **End on the goal.** The last 2–3 s carry a clear CTA or payoff, not a fade to black.

Write the shot list as a table: `# | dur | visual | on-screen text | VO line | source (AI / stock / code / user asset)`.
This table is what maps onto the render spec in step 4.

## 3. Pick the production route

| Route | Use when | How |
|---|---|---|
| **A. AI-generated footage** | Cinematic or realistic shots that don't exist yet | Write one prompt per shot using `references/ai-video-prompting.md`. The user, or an API they have, generates the clips. Then use route C to assemble them |
| **B. Code-rendered** | Text-led explainers, promos, slideshows, quote/stat videos, Ken Burns over images | `scripts/render.py` with a JSON spec. Runs fully local |
| **C. Hybrid (most common)** | AI or stock clips plus captions, titles, VO and music | Put the clips in the spec as `video` scenes and render with `scripts/render.py` |

Never claim a clip was generated by an AI model unless one was actually called in
this session. When no video-generation API is available, deliver the prompts and an
assembly spec that already points at the clip filenames the user will drop in.

## 4. Render

`scripts/render.py` turns a JSON spec into a finished H.264/AAC MP4. It handles:
- cover-crop of any input to the preset size
- Ken Burns motion on stills
- crossfades
- styled burned-in titles and word-chunked captions
- voiceover with music ducked under it
- loudness normalized to −14 LUFS (−1.5 dBTP)
- a `+faststart` MP4

```bash
python3 .claude/skills/video-production/scripts/render.py spec.json            # render
python3 .claude/skills/video-production/scripts/render.py spec.json --dry-run  # print the plan only
```

Start from `templates/spec.example.json`. Paths in the spec are resolved relative to the spec file. Main fields:

- `preset`: `vertical` (1080×1920), `landscape` (1920×1080), `square` (1080×1080) or `portrait` (1080×1350)
- `scenes[]`: each scene has a `duration` and one of `image`, `video` or `color`. Optional fields are `motion` (`zoom_in`, `zoom_out`, `pan_left`, `pan_right`, `none`), `title` (large centered text), `caption` (lower text, auto-split into 3–4 word chunks) and `start` (offset into a video file)
- `voiceover`, `music`, `music_volume` (default 0.12), `fit_to_voiceover` (stretches the scenes so they cover the whole VO)
- `transition`: `{ "type": "fade", "duration": 0.35 }`. Any ffmpeg xfade name works, e.g. `fadeblack`, `slideleft` or `circleopen`. Use `"duration": 0` for hard cuts
- `style`: `font`, `accent` (hex color for the active caption chunk), `caption_size`, `title_size`

For anything the spec can't express, such as speed ramps, picture-in-picture or
reframing, use the tested commands in `references/ffmpeg-recipes.md`.

Voiceover: if the user has a TTS provider (ElevenLabs, OpenAI, etc.) or a recording,
use it. Don't present a robotic placeholder voice as final.

## 5. QA, which is required before delivery

```bash
python3 .claude/skills/video-production/scripts/qa.py out.mp4 --preset vertical
```

It reports the following and writes `out_contact.png`, a frame contact sheet:
- resolution, fps and codec
- pix_fmt (yuv420p is needed for compatibility)
- whether there is an audio stream and whether the file is faststart
- integrated loudness and true peak
- black or frozen stretches

**Open the contact sheet image and look at it.** Check for:
- text cut off or sitting in platform UI zones (bottom ~20% and right ~12% on 9:16)
- unreadable contrast
- awkward crops of faces or products
- a dead first frame

Fix every FAIL and re-run QA. Report any remaining WARN to the user and don't hide it.

## 6. Deliver

Give the user:
- the MP4 path
- the contact sheet
- runtime and loudness
- the spec, so they can tweak and re-render
- for route A, the prompt sheet

If the video is for several platforms, render one file per aspect ratio from the same
spec by changing `preset`, rather than letterboxing one master.

## Quality bar (checked against the contact sheet and a full playback)

- The first frame is already interesting, because it is the thumbnail on many feeds.
- Captions are ≤ 2 lines, high contrast with an outline or box, and stay clear of the platform UI.
- Text stays on screen long enough to read twice (about 0.3 s per word, minimum 1 s).
- No shot holds still for more than about 4 s without motion or a change.
- Audio is −14 LUFS ±1, peaks stay under −1 dBTP, music sits ~15–20 dB under the voice, and there are no clicks at cuts.
- Fonts, colors and logo placement stay consistent across the whole video.
- The CTA is on screen for at least 2 s at the end.
